# Changelog

All notable changes to Vidimus will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.1.0a3] — 2026-10-06

### Added
- `verify(attestation, trusted_keys=...)` and `vidimus verify --trusted-key / --trusted-keys-file`: pin the issuer key (fingerprint or hex public key). A pinned verification fails if the issuer is not listed.

- `Attestation.merkle_scheme` (`"rfc6962-v1"` | `"legacy-duplicate"`). New attestations are `rfc6962-v1` and the field is covered by the signature (it cannot be downgraded). Files without the field are loaded as `legacy-duplicate`, still verify (the field is left out of their signed bytes and anchor hash), recompute their root with the old rule in `verify --traces`, and make `verify` warn. `prove` refuses legacy attestations.

### Changed (behaviour)
- Default store is now a persistent DuckDB file per workspace (`<home>/workspaces/<workspace>/traces.duckdb`; `$VIDIMUS_HOME` overrides `~/.vidimus`). `init(store="memory")` or `VIDIMUS_STORE=memory` keeps the ephemeral store. Without the `duckdb` extra it falls back to memory with a `RuntimeWarning`.
- `vidimus init` remembers the workspace (`<home>/config.json`) and no longer wipes existing traces; use `vidimus init --reset [--yes]`. `attest`, `prove` and `export` now work across terminals.

### Documentation
- README: replaced the absolute claim that no other tool proves integrity; added a "Known limitations" section (key pinning, garbage-in/garbage-out, shared judge bias, optional checks, in-process store).

### Breaking
- `MerkleTree` now follows RFC 6962 (split at the largest power of two < n) instead of duplicating the last node. **Merkle roots change for any trace count that is not a power of two**, so attestations generated by earlier versions will not recompute with this version. The old rule also made `[a,b,c]` and `[a,b,c,c]` collide.
- `verify_inclusion()` now returns `False` when `leaf_index >= tree_size` or when the path length is not the one required for that index and tree size. Inclusion proofs have variable length (RFC 6962 audit paths).

- `vidimus verify --traces <export>`: recomputes the Merkle root over the exported traces (JSONL or JSON array) and compares it to the signed root; `vidimus.audit.attest.verify_traces()` is the library equivalent.
- `vidimus verify --check-anchor --rpc-url <url>`: checks the on-chain anchor (needs `vidimus[onchain]`); fatal if not found or if block/tx/chain differ from the report.
- `vidimus export --against report.json`: writes the traces covered by an attestation, as input for `verify --traces`.

### Fixed
- `vidimus verify` printed "Merkle root matches N traces" and an on-chain anchor line without checking either. It now reports `not checked` unless `--traces` / `--check-anchor` ran, and exits non-zero on a mismatch.
- `vidimus prove` double-hashed leaves (`sha256(canonicalize(trace))` fed into a tree that hashes again), so it never reproduced the root signed by `attest` and always failed. Both now share `vidimus.audit.attest.leaf_bytes(trace)`.

### Changed
- `verify()` without `trusted_keys` now returns the warning "issuer key not pinned: signature proves integrity, not identity".

## [0.1.0a2] — 2026-05-17

Implementation completeness milestone. Every component promised in the README is now backed by working code — no more stubs masquerading as features.

### Added

**Real LLM judges** (`src/vidimus/audit/judges.py`)
- `OpenAIJudge`: GPT-4o / GPT-4 / any OpenAI chat model with structured JSON output, exponential retry, lazy SDK import
- `AnthropicJudge`: Claude Sonnet / Haiku via the Messages API, same retry semantics
- `OllamaJudge`: local OSS models (Llama 3, Mistral, etc.) over HTTP, no API key needed
- Shared judge prompt template for consistent scoring across backends
- Response parser handling strict JSON, markdown-fenced JSON, and regex fallback

**DuckDB persistent storage** (`src/vidimus/storage/duckdb_store.py`)
- Full SQL schema with indexes (traces, merkle_checkpoints)
- Same interface as `InMemoryStore`, drop-in replacement
- Context manager support
- 13 new tests covering CRUD, time-window filtering, checkpoints

**OpenTelemetry HTTP receiver** (`src/vidimus/receivers/otlp.py`)
- FastAPI server listening on port 4318 (OTel standard)
- Full OTLP/JSON parser: resource spans → scope spans → span groups by trace_id
- Health endpoint at `/health`
- Drop-in alongside Opik, Langfuse, LangChain, raw OTel SDK

**On-chain anchoring** (`src/vidimus/audit/anchor.py`)
- `OnchainAnchorer` for EVM chains (BNB, Ethereum, Base, Sepolia, custom)
- web3.py-backed `anchor()` and `verify_anchor()` methods
- Deterministic anchor hash excluding the signature field
- Default RPC URLs for common networks

**New CLI commands**
- `vidimus prove <trace_id> --against report.json` — Merkle inclusion proof
- `vidimus serve --port 4318` — start the OTLP HTTP receiver

**Real integration examples**
- `examples/opik_integration.py` — dual decoration with `@opik.track` + `@vidimus.audit`
- `examples/langchain_integration.py` — LangChain QA chain instrumented with Vidimus
- `examples/rag_production.py` — sentence-transformers + FAISS + Ollama production RAG

**Optional dependency extras** (`pyproject.toml`)
- `vidimus[openai]`, `vidimus[anthropic]`, `vidimus[ollama]`
- `vidimus[duckdb]`, `vidimus[otel]`, `vidimus[onchain]`
- `vidimus[rag]`, `vidimus[all]`

### Changed
- Test count: **68 → 136** passing tests
- All `# TODO v0.2:` markers removed; every promise is now backed by code
- pyproject.toml URLs point to `github.com/kabNath/vidimus`
- Badge configuration in README updated (PyPI placeholder replaced with static version badge)

### Fixed
- `build_judges()` now accepts pre-instantiated `Judge` instances in addition to identifier strings
- OTLP receiver correctly handles empty `parentSpanId` (treats as `None`)

## [0.1.0a1] — 2026-05-15

Initial public alpha release of Module A.

### Added
- RFC 8785 canonical JSON serializer
- RFC 6962 SHA-256 Merkle tree with inclusion proofs
- Ed25519 key generation, signing, and verification
- Bootstrap confidence intervals (vectorized numpy)
- Cohen's kappa, Fleiss's kappa, Krippendorff's alpha
- Pydantic v2 schemas
- Deterministic `StubJudge`
- `attest()` orchestrator and `verify()` with fatal/warning separation
- `@vidimus.audit` decorator and `vidimus.trace()` context manager
- Thread-safe in-memory trace store
- CLI: `init`, `version`, `keys generate|list`, `attest`, `verify`
- `VidimusAnchor.sol` smart contract source
- Docker multi-stage build
- 68 tests, CI workflow
